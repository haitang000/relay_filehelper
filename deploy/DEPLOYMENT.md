# 当前服务器部署记录

- 公网地址：`https://files.haitang000.cn`，通过用户配置的反向代理访问。
- 部署方式：面板 → 网站 → Node 项目，项目名 `relay`，直接运行 Node.js。
- 运行时：面板 Node.js `v24.22.0`，运行用户 `www`。
- 应用目录：`/www/wwwroot/relay`。
- 启动命令：`node /www/wwwroot/relay/start.mjs`。
- 监听端口：`0.0.0.0:3080`，已通过创建项目时的放行端口选项配置。
- 数据目录：`/www/wwwroot/relay/data`，包含 SQLite、上传文件和临时文件。
- 当前配置：单文件 1 GiB、每批 20 个、每账号并发 2 个、每房间 2 GiB、全站 8 GiB，注册开放。
- `.env` 的 `PUBLIC_ORIGIN=https://files.haitang000.cn`、`COOKIE_SECURE=true`；后端仍监听 3080 端口。用户应通过 HTTPS 域名登录。
- `TRUST_PROXY=0` 保持不变；当前后端端口仍公开，避免直接信任可由客户端伪造的转发头。若之后将后端限制为仅反向代理可访问，可按可信代理链调整此配置。

首次访问后自行注册应用账号。面板里可通过项目「设置 → 服务」重启，通过「项目日志」排查问题。

## 生成无需服务器编译的部署包

```sh
npm run package:server
```

输出 `.deployment/relay-server.tar.gz`。压缩包包含编译好的前端、服务端、68 个纯 JavaScript 运行依赖、独立启动入口以及示例服务器配置，不包含本地账号和上传数据。`release.json` 记录源码与构建资源的 SHA-256 校验值。

新服务器安装 Node.js 24 后，将包上传到 `/www/wwwroot`，解压产生 `relay` 目录，检查 `.env` 中的地址和端口，再以该目录创建 Node 项目。部署包已含 `node_modules`，可选择「不安装 node_module」，不需要在小内存服务器上编译前端或在线安装依赖。

## 更新与数据保留

仅更新界面时，运行 `npm run package:web`，上传 `.deployment/relay-web.tar.gz` 并解压到 `/www/wwwroot/relay`。包内只有 `dist` 的前端资源，不含 `.env` 或 `data`；先写入带内容哈希的资源，最后替换首页入口，保留旧资源供已打开的页面使用，无需重启服务。发布后刷新浏览器加载新版。

更新前先在面板停止 `relay`，并备份整个应用目录。上传新包到临时目录，将新包的 `server`、`dist`、`node_modules`、`start.mjs`、两个 package 文件和 `release.json` 替换到应用目录。保留服务器现有 `.env` 和整个 `data`，不要直接用示例配置覆盖生产配置。保持目录归属 `www`，再从面板启动并检查 `/api/health`。

备份账号和文件时，停止项目后备份整个 `data`，同时保管 `.env`。恢复时使用完整的数据目录；过期文件会在应用启动后补清理。
